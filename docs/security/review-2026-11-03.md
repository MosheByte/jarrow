# Security review, 2026-11-03

A review of the whole repository as it was on `main` at [`e51b0d5`](https://github.com/jarrow-dev/jarrow/commit/e51b0d5) (milestone M1, harness core merged). It was done by the AI build agent (Claude) for the project owner, against the security requirements and trust boundaries in the [assurance case](assurance-case.md). It is the project's first security review. The next one is due before release v0.1 (milestone M5), or within 12 months, whichever comes first.

Every finding is listed, including the ones that are not exploitable today. Line numbers refer to `e51b0d5`. Fixes landed in the pull request that added this file; findings that need the owner or another change have an issue.

Tools used besides reading: `actionlint` 1.7 on every workflow, the existing test suites, and `gh api` for settings. CodeQL (`codeql.yml`), OpenSSF Scorecard (`scorecard.yml`), `cargo deny` and ClusterFuzzLite run in CI already; this review did not replace them.

Severity is the likely impact on the project's security requirements, weighted by how hard the attack is: **High** means an outside attacker can reach a secret or change what users run; **Medium** needs an unlikely precondition (a malicious dependency release, a compromised bot) but then reaches a secret or another project; **Low** is a weakness with limited impact or one that needs a maintainer to act; **Informational** is not a vulnerability today.

## What was checked and found sound

These are the properties the assurance case relies on, checked one by one during the review.

- **No workflow interpolates untrusted text into a shell.** Every value a pull request, issue or discussion controls (branch names, titles, bodies, artifact contents) reaches `run:` scripts through `env:`, never through `${{ }}` in the script. The one `${{ }}` inside a `with:` command (`deploy-site.yml:87`) is a branch name reduced to `[A-Za-z0-9._/-]` first, and only same-repository branches get there.
- **`pull_request_target` and `workflow_run` never run pull request code.** `labeler.yml` uses the labeler action, which reads the changed-file list through the API, with `pull-requests: write` only. `welcome.yml` has no checkout at all, treats artifacts as data with size caps, and defuses mentions and markers before posting.
- **Least privilege.** Every workflow sets `permissions: contents: read` at the top, and each job asks only for what it uses (`contents: write` only for release and bot jobs on `main`). Every checkout sets `persist-credentials: false`. Every action is pinned to a full commit SHA with a version comment.
- **Secrets reach only their own service.** `CLOUDFLARE_API_TOKEN` is read only by `wrangler`; `BOT_DEPLOY_KEY` is written to a mode-0600 file, used through `GIT_SSH_COMMAND` with GitHub's host keys from `gh api meta`, and removed by a trap; `wrangler whoami` output, which contains the account e-mail, is kept out of the log. Secret scanning and push protection are enabled on the repository (checked with `gh api repos/jarrow-dev/jarrow`), and `tools/pr_ready.py` refuses tracked files that look like tokens or private keys.
- **The JAR reader bounds everything it reads.** Entry count, per-entry and total uncompressed size are checked against the declared sizes before anything is decompressed, the inflater is capped at the declared size plus one byte, overlapping entries (the "better zip bomb") are refused, CRC and sizes must match, nested jars share one budget and stop at depth 8 (hard cap 64), and every offset uses checked arithmetic. `#![forbid(unsafe_code)]`, no `unwrap` or `expect` in library code, and the `no_panic`, `guards` and `zip64` tests plus ClusterFuzzLite with AddressSanitizer cover it.
- **The class-file parser cannot be made to allocate or recurse without bound.** List capacities are capped by the bytes left (`capacity()` in `bytes.rs`), switch tables are checked against the remaining code, and annotation nesting is limited (`MAX_NESTING`).
- **Downloads are hash-verified.** The harness refuses an artifact without a pinned hash, verifies size and every pinned hash before a file is used, replaces a cached file that no longer matches, and allows plain HTTP only to loopback (for tests). Child processes (the Minecraft servers) start with a cleared environment plus an allowlist, so no secret reaches them. The harness refuses to start a server unless the owner's EULA gate is open (`crates/harness/src/eula.rs`).
- **The site encodes its output.** Astro escapes every interpolated value, no page uses `set:html`, and board rows are validated before rendering: `page_url` must be an `https:` URL and `report_url` is never taken from the data.

## Site headers

The policy shipped with this review (`site/src/lib/headers.ts`, `site/public/_headers`):

```
Content-Security-Policy: default-src 'none'; script-src 'self' 'wasm-unsafe-eval' <11 sha256 hashes>; style-src 'self' 'unsafe-inline'; img-src 'self' data: https://avatars.githubusercontent.com https://github.com; font-src 'self' data:; connect-src 'self'; worker-src 'self'; manifest-src 'self'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=(), serial=(), hid=(), browsing-topics=()
```

Why each allowance is there:

- The 11 hashes are the inline scripts the build emits: the theme script in `Base.astro` and its `ThemeToggle` module, and Starlight's theme, sidebar, table-of-contents and search scripts. No other inline script runs.
- `'wasm-unsafe-eval'` lets the docs search (Pagefind) compile its WebAssembly. It does not allow `eval()` or `new Function()`.
- `style-src 'unsafe-inline'`: Starlight writes `style` attributes (`style="--depth: 0"`, about 400 of them on the docs pages), and Astro inlines small component stylesheets. Styles cannot run script; this is the one permissive value.
- `img-src` names GitHub's avatar host because `/about` and `/contributors` show avatars, and `github.com` because the home page shows the CI badge.
- `font-src data:`: one bundled font face is inlined as a data URI.

How it was verified: `npm run build` (which now ends with `scripts/csp-check.mjs`: 20 pages, 11 inline scripts, all allowed); `npm test`; `wrangler pages dev ./dist`, then `curl -I` on `/`, `/board/`, `/api/board.json` (server-rendered, headers from `src/middleware.ts`), `/about/`, `/docs/`, `/pagefind/pagefind-worker.js` and a 404 (static, headers from `_headers`): all carry the six headers. In a browser on the local server, with a `securitypolicyviolation` listener: the docs search returned results, the theme toggle worked on `/`, the custom elements of the docs pages were defined, fonts loaded, the six avatars and the CI badge loaded, and no violation was reported.
