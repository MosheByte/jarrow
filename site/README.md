# site/

The Jarrow website: landing page, board, docs. Astro 7 + Starlight + Tailwind 4, deployed to the Cloudflare Pages project `jarrow` (https://jarrow.pages.dev).

## Commands

Node 22.18 or later (the unit tests use Node's built-in TypeScript type stripping).

```sh
npm ci
npm run dev        # astro dev, with local KV/D1/R2 simulations from wrangler.toml
npm run build      # astro build, then scripts/pages-assemble.mjs turns dist/ into a Pages directory
npm run preview    # wrangler pages dev ./dist on http://127.0.0.1:8788 (build first)
npm run check      # astro check (TypeScript and .astro diagnostics)
npm test           # node --test: board loader, link rewriting, headers, route list
```

Set `ASTRO_TELEMETRY_DISABLED=1` in CI.

## How the pieces fit

| Path | What it is |
| --- | --- |
| `src/lib/site.ts` | `SITE_URL` and every other site-wide constant. Change the domain here and in `wrangler.toml` `[vars]` |
| `src/lib/board.ts` | The `BoardJson` type (schema 2: all 12 directions, a column for each measured one; contract in `docs/board.md`) and `loadBoard()`, the one loader for `board.json` from KV. Never throws; a missing binding or key gives the empty board |
| `src/lib/runtime.ts` | The only module that imports `cloudflare:workers` |
| `src/pages/index.astro`, `board.astro`, `api/board.json.ts` | Server-rendered (`export const prerender = false`); everything else is prerendered |
| `src/content/docs/docs/` | Starlight docs, served under `/docs/` |
| `src/styles/tokens.css` | Generated by `crates/report`. Never edit it by hand |
| `src/styles/global.css`, `site.css`, `starlight.css` | Tailwind setup and the mapping of Starlight's variables to the `--jw-*` tokens |
| `wrangler.toml` | The Pages config and the only place bindings are declared |
| `scripts/wrangler-config.mjs` | Derives the Workers-shaped config the Astro adapter needs (`wrangler.adapter.jsonc`, gitignored) from `wrangler.toml` |
| `scripts/pages-assemble.mjs` | After `astro build`: moves `dist/client/*` to `dist/`, the server to `dist/_worker.js/`, and writes `dist/_routes.json` from the server-rendered pages |
| `BRAND-SOURCES.md` | Every icon, logo and font, and its license |

## Why the build is assembled for Pages

`@astrojs/cloudflare` 13 and later build for Cloudflare Workers only (static files in `dist/client`, the worker in `dist/server`) and refuse a wrangler config with `pages_build_output_dir`. The project is a classic Pages project (D-004), so `scripts/pages-assemble.mjs` rearranges the output into Pages advanced mode, and `scripts/wrangler-config.mjs` gives the adapter a Workers-shaped copy of `wrangler.toml`. Moving to Workers static assets later means deleting those two steps and deploying `dist/server/wrangler.json` with `wrangler deploy`.

## Board data

The nightly writes `board.json` to the `BOARD` KV namespace. To try the pages with data locally, put a file into the local simulation only:

```sh
npx wrangler kv key put board.json --path ./my-board.json --binding BOARD --local
npm run preview
npx wrangler kv key delete board.json --binding BOARD --local
```

Never write sample rows to the real namespace: the board shows only what the nightly measured.
